Pecan · control plane

One small CLI for every important GUI action.

KISS plan
server stays authoritative

Decision

Extend the existing pecan binary. Do not build a second daemon, TUI, plugin system, or generic runtime abstraction.

The running Pecan server already owns Pi workers and exposes the GUI's JSON API. The CLI becomes a thin, scriptable client of that same API. Humans get readable output; agents use --json.

Orchestrator path

orchestrator
  ├─ pecan session create --cwd /repo --json     → A
  ├─ pecan session create --cwd /repo --json     → B
  ├─ pecan session send A --message "Inspect API" 
  ├─ pecan session send B --message "Inspect UI"
  ├─ pecan session wait A --until idle --json
  ├─ pecan session steer B --message "Use A's findings: ..."
  └─ pecan session wait B --until settled --json

Pi Subagents remains the native way for one Pi agent to spawn and wait for children. The CLI also lets an external orchestrator control known session IDs directly.

One config

Where to find the server:

--server URL
PECAN_SERVER_URL

Default: http://127.0.0.1:7614. No config file for v1.

One output rule

Every mutating command supports:

human text
--json

JSON goes to stdout. Diagnostics go to stderr. Exit 0 only after accepted/complete semantics are known.

One safety rule

Bounded timeouts everywhere. Ship requires an explicit flag and capability token. No arbitrary shell execution through Pecan.

Implementation slices

1

Thin client + grammar

Add a small async HTTP client and command parser. Centralize URL resolution, request errors, timeout, and JSON output. Reuse existing API schemas where practical.

Proof: list/create return stable JSON and readable errors.
2

Session control

Implement create, send, steer, queue, abort, state, model, thinking, and respond. Keep mode validation aligned with the server's existing conflict behavior.

Proof: create two sessions, send to both, steer one, answer an AskUser request.
3

Wait + events

Consume the existing SSE stream and expose filtered JSONL events. wait exits on idle, settled, or timeout; it never polls aggressively.

Proof: orchestrator script runs A → B handoff deterministically.
4

Parity extras

Add project curation, pin/settle, diff, and guarded ship only after the control loop is solid. Add aliases for current commands.

Proof: command inventory maps to every GUI mutation and read.

Explicitly not doing

  • No second worker/runtime implementation
  • No abstraction for other UIs/runtimes
  • No background orchestration daemon
  • No command to execute arbitrary code
  • No broad CLI redesign before the control loop works

Done means

An AI agent can start sessions, talk to each session, steer or queue work, answer blocking questions, observe events, and wait for completion using only pecan ... --json.

That is the smallest useful control plane. Everything else remains GUI polish or a later decision.
